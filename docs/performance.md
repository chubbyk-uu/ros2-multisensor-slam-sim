# 性能与旋转标定记录

本文记录 2D SLAM 基线的性能优化和里程计标定结果。数值用于同一测试环境下的前后对比，不代表所有硬件上的固定性能。

## 性能优化

自研 C++ SLAM 使用 `RelWithDebInfo` 作为默认构建类型，对应 GCC/Clang
常用的 `-O2 -g -DNDEBUG`。复现性能数据前应显式执行：

```bash
colcon build --packages-select slam_robot_slam --symlink-install \
  --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo
```

不要使用 `CMAKE_BUILD_TYPE` 为空的构建结果评估扫描匹配性能；这种情况下
GCC 默认等同 `-O0`。

2026-07-30 使用审查时的固定合成数据进行单核对比：

| 操作 | 无优化构建 | `-O2` |
| --- | ---: | ---: |
| 局部子图匹配（20 关键帧 / 7200 点） | 42.6 ms | 19.4 ms |
| 回环候选匹配（11 关键帧） | 38.6 ms | 19.5 ms |
| 单关键帧射线积分（360 射线） | 1.8 ms | 0.30 ms |

回环候选匹配和 Ceres 优化现在使用不可变状态快照在后台线程执行，激光
回调只负责创建共享点集引用和事务式合并完成结果。地图重建仍按仿真时钟
每周期处理固定数量关键帧，并以“完成当前版本、只排队最新版本”的方式
避免重复回环导致重建进度持续归零。

相关匹配的粗搜索步长和精搜索窗口已解耦。局部匹配默认候选数由约
`6798` 降至约 `1620`，同时精搜索仍覆盖粗搜索半步误差；回环采用
`0.10` 粗步长覆盖 `0.60 m / 0.50 rad` 窗口，再在 `0.05` 窗口内以
`0.01` 精配，不再让“粗搜索”退化为栅格分辨率上的穷举。

候选评分原先分别调用 `supports()` 和 `likelihood()`，每个扫描点会执行
两次世界坐标到栅格坐标转换。合并为一次采样后，同一轮审查微基准结果为：

| 操作 | 双次查表 | 单次查表 | 降幅 |
| --- | ---: | ---: | ---: |
| 局部候选评分 | 7.3 ms | 5.2 ms | 约 29% |
| 回环候选评分 | 12.2 ms | 8.1 ms | 约 34% |

弱方向从 `0.05 m` 增大到 `0.30 m`。上表记录的是这版实现，其纵向峰值
相对未处理基线下降约 81%。

上表的 392 是激光里程计消息数，不是独立匹配次数：运动不足和拒配路径会
重复发布上一次协方差，因此不能用它推导退化检出率。加入逐次匹配诊断后，
同一默认配置再次执行 25 m 单向回归，共发生 314 次真实匹配，其中 rank 1
为 190 次、rank 2 为 124 次；在这次固定仿真中的检出比例为 60.5%，漏检
比例为 39.5%。ratio 直方图按边界
`[0, .01, .025, .05, .10, .25, .50, 1]` 的计数为
`[91, 29, 70, 94, 30, 0, 0]`。本次纵向峰值 / 最终误差为
`0.130 m / 0.080 m`，横向峰值为 `0.026 m`，无拒配或错误回环。

真实角采样单元测试使用与模型一致的 720 束、stride 2、12 m 量程，覆盖
1/5/20 个关键帧与 `0/0.0025/0.005/0.01 m` 测距噪声。12 种组合中旧版
响应曲面检测器给出 3 次 rank 1、9 次 rank 2；rank 1 时保留了准确的
`0.10 m` 里程计预测，rank 2 时结果被相关匹配拉回 `0.02～0.08 m`。
这说明处理在触发时有效，但响应 Hessian 会把光束端点混叠误当成沿走廊
方向的信息，且结果随子图深度与噪声变化。

当前实现改为在每帧扫描内部保留原始光束索引和量程，只在索引连续且
相邻点距离满足 `0.05 m + 0.05 × range` 的七点窗口中拟合局部直线法向。
归一化矩阵 `Σnᵢnᵢᵀ / N` 的特征值比表示两个平移方向的相对表面支撑，
未归一化特征值则直接表示有效法向数量。弱方向激光修正比例连续取
`min(1, ratio / 0.05)`，避免旧版 rank 硬切换。

上述 12 种组合在新检测器下全部为 rank 1，纵向估计相对准确的
`0.10 m` 预测最大偏差不超过 `0.011 m`，不再随子图深度翻转。完整 25 m
Gazebo 回归发生 314 次真实匹配，rank 1 / rank 2 为 `226 / 88`；端墙和
非对称入口/出口锚点可见时存在真实纵向法向，因此 rank 2 是预期结果，
中部长平行墙稳定为 rank 1。本次纵向峰值 / 最终误差为
`0.185 m / 0.185 m`，横向峰值 `0.040 m`，最大前端间隔 `0.100 s`，无
拒配或错误回环。正常场景的独立闸门已加入长闭环和三档快速旋转回归，
两者分别覆盖 209 和 651 次真实匹配，均要求退化误报严格为零。

同一配置随后重复执行单向测试，纵向峰值分别为 `0.210 m` 和 `0.150 m`，
其余横向、航向、前端间隔和无错误回环判据均通过。因此自动回归使用
`0.25 m` 单向连续上限，在保留约 70% 以上基线改善要求的同时覆盖出口
锚点处约一个栅格的运行波动。

当前配置的主要取值：

- Gazebo 物理循环：250 Hz。
- 2D LiDAR：10 Hz。
- 轮式里程计与 `odom -> base_footprint`：50 Hz。
- SLAM 地图更新周期：2 s。
- Gazebo 不绘制 LiDAR 射线，激光仍通过 `/scan` 在 RViz 中显示。
- RViz 默认关闭 TF 可视化，需要排查坐标系时可手动启用。

里程计频率使用 50 Hz，是因为它既能整除 250 Hz 物理循环，也能与
10 Hz LiDAR 周期对齐。此前请求 30 Hz 时，Gazebo 实际按 36 ms 周期发布
TF，部分激光帧会比最新 TF 提前最多约 28 ms，导致 RViz 的
`Message Filter` 状态在 `OK` 和 `Error` 之间闪烁。调整后实测 TF 周期
稳定为 20 ms，连续 201 帧激光中没有出现时间戳领先 TF。

Gazebo 的物理、传感器和场景管理仍主要运行在 CPU 上；GPU 负责 GUI 的三维渲染，因此启用 D3D12 不会让 Gazebo Server 的物理计算转移到 GPU。

## 互斥 LiDAR 与 IMU 基线

2026-08-03 在同一台 WSL2 主机、同一室内世界、实时率稳定后采样。两种
模型均启用 100 Hz IMU，但 LiDAR 互斥；表中不计 Gazebo GUI 和 RViz：

| 传感器配置 | Gazebo Server CPU / RSS | bridge CPU / RSS | 实时率 |
| --- | ---: | ---: | ---: |
| 2D：720 束 × 10 Hz | 约 29.0% / 347 MiB | 约 5.6% / 55 MiB | 约 1.0 |
| 3D：720 × 16 × 10 Hz | 约 29.4% / 348 MiB | 约 6.4% / 57 MiB | 约 1.0 |

3D `PointCloud2` 每帧 `368640 B`，原始消息载荷约 `3.52 MiB/s`；字段为
`x/y/z/intensity/ring`，`frame_id=lidar_3d_link`，实测频率
`10.003 Hz`。3D 配置下 `/scan` 无消息，证明没有同时运行 2D 雷达。
本轮只记录进程 CPU/RSS 和原始 ROS 消息带宽，尚未把 GPU 占用和后续
点云算法延迟纳入对比。

IMU 静止实测约 `100 Hz`，`frame_id=imu_link`，重力方向为
`linear_acceleration.z ≈ +9.81 m/s²`；陀螺 z 轴标准差约
`0.002 rad/s`，与模型噪声参数一致。

| 正常附着 | EKF `/odom` | 0.0010 m | 0.013° |
| 正常附着 | 自研 2D SLAM | 0.0059 m | 0.588° |
| 左轮低摩擦 `0.15` | 原始轮速 `/wheel/odom` | 0.0309 m | 13.753° |
| 左轮低摩擦 `0.15` | EKF `/odom` | 0.0309 m | 0.175° |
| 左轮低摩擦 `0.15` | 自研 2D SLAM | 0.0025 m | 0.174° |

EKF 只采用轮速的平面线速度和 IMU 的偏航角速度；不重复融合轮速偏航，
也不使用 IMU 的绝对姿态或线加速度。它在单侧打滑时将局部里程计航向
误差从约 `13.75°` 降到 `0.18°`，作用很明确；不同随机 IMU 偏置运行中
曾测得 `0.04°`。自研 2D SLAM 已通过激光匹配把同一打滑测试的最终
航向修正到约 `0.2°`，因此短路线的最终
地图/轨迹没有呈现与 EKF 同量级的提升，并会受扫描噪声产生小幅运行间
波动。结论是：IMU 显著增强退化或打滑时的局部运动预测，但不能替代
LiDAR 约束，也不应宣称加入后所有 2D 地图都会更准。默认仍保留
`odometry_mode:=wheel` 作为冻结回归基线。

## 旋转与里程计标定

机器人驱动轮几何中心距为 `0.34 m`。考虑 Gazebo ODE 中有限宽圆柱轮的有效接触位置，经过原地旋转标定，差速驱动和里程计使用的有效轮距为 `0.306 m`。该参数不会改变模型几何或 `base_footprint` 的位置。

优化后进行约 127° 原地旋转：

- 轮式里程计相对 Gazebo 真值的航向误差约 `0.31°`。
- SLAM 相对 Gazebo 真值的航向误差约 `0.29°`。
- SLAM 平移偏差约 `1.5 mm`。

SLAM 的旋转关键帧阈值为 `0.05 rad`，用于减小起转和停转时激光相对地图的瞬时偏移。10 Hz LiDAR 与 0.05 m 栅格分辨率下，小角度转弯仍可能出现几厘米的短暂误差，应以停稳后的重新对齐和整张地图是否持续重影作为判断标准。

## 复现基础运动测试

短时发送直行指令：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.20}, angular: {z: 0.0}}" -r 10
```

结束速度发布后发送一次零速度：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist \
  "{linear: {x: 0.0}, angular: {z: 0.0}}" --once
```

测试时应同时记录 Gazebo 真值、`/odom`、SLAM 位姿、实时率以及相关进程 CPU，占用变化需要在相同场景和显示配置下比较。
