# 2026-07-30 自研 SLAM 工程审查整改

本文记录工程审查意见的处理结果，用于区分已经修复并完成回归的问题、
2D 基线冻结时有意保留的设计，以及不接入实时链路的实验代码。

## 已完成的高、中优先级整改

| 审查项 | 处理结果 |
| --- | --- |
| 无优化构建 | 默认构建类型设为 `RelWithDebInfo`，README 的构建命令显式传入该类型。 |
| 回环阻塞激光回调 | 回环候选匹配和 Ceres 优化改为后台任务，只读取不可变状态快照；主线程事务式合并结果。 |
| 地图重建可能饥饿 | 当前重建不再被新回环清零，只保留最新待处理快照；调度状态已抽出并有单元测试。 |
| 未捕获异常 | 节点构造、单帧扫描处理、地图发布和后台结果合并均有异常边界和明确日志。 |
| 扫描元数据缺少校验 | LaserScan、里程计、TF、投影点、位姿图输入均检查有限性和有效范围。 |
| Path 带宽与线性搬移 | 轨迹按运动量采样、2 Hz 发布、限制长度；到达上限后按批次裁剪，避免每帧搬移。 |
| 墙钟定时器 | 地图发布和分批重建使用节点时钟，遵循 `use_sim_time`。 |
| 失败回环污染位姿图 | 后台只优化图副本；只有完整验证和优化成功后才向实时图事务式提交约束。 |
| 回环仅有分数门限 | 增加累计行程、连续候选链、支撑占比和最大平移/旋转修正量约束。 |
| 回环搜索语义不一致 | 候选半径和匹配搜索窗口对齐；粗搜索与精搜索使用独立窗口和步长。 |
| 新区域拉低匹配分数 | 分数只对相关栅格范围内的点归一化，支撑点占比作为独立门限。 |
| 地图重建异常状态 | 排队版本启动失败时清空重建状态，不让异常穿透定时器或留下过期 active 快照。 |
| 回环提交后日志歧义 | 提交前拒绝与提交后 Path/地图刷新失败使用不同异常边界和日志。 |
| 热循环重复查表 | 支撑检查与似然读取合并为一次栅格采样，审查微基准降低约 29%～34%。 |
| 弱回环保护门限 | 连续候选链由 3 提高到 10，最大旋转修正由 0.50 rad 收紧到 0.25 rad。 |
| 平行走廊纵向滑动 | 已用保留光束索引、检查距离断裂的局部扫描法向替换响应 Hessian，并按信息比值连续缩放弱方向修正；逐次匹配诊断保留用于场景回归。 |
| 退化回环仍以各向同性高权重建边 | 关键帧保存单帧法向可观测性；后台候选 rank 小于 2 时保守拒绝，正常 rank 2 回环保持原权重。 |
| 位姿图只能表达标量平移权重 | 约束已升级为对称 3×3 信息矩阵，Ceres 用 Cholesky 因子白化；处理器支持弱方向低信息回环。 |
| 航位推算路径复用陈旧协方差 | 成功匹配重置观测协方差；拒配和运动不足路径按相邻里程计行程/转角增量累计过程噪声。 |
| 走廊回归只有单边事件下限 | 入口/出口之外的中段单独统计逐次匹配 rank，要求样本数和退化检出比例同时达标。 |
| EKF 输入协方差全零 | Gazebo 裸消息先经过薄适配节点，轮速横向/纵向速度与 IMU 测量均使用有限、非零、可调协方差。 |
| IMU 工具没有失败判据 | 正常路面限制航向劣化，打滑场景要求相对轮速改善，并对误差上限和协方差契约返回明确退出码。 |

## 已完成的可维护性整改

- `Point2D` 已移到纯几何头文件，基础几何库不再传递依赖
  `sensor_msgs`。
- 关键帧容器和位姿图节点下标有显式不变式检查，插入和回环合并为事务式。
- 补齐库导出、直接依赖、维护者信息，并把各包最低 CMake 版本提高到
  3.10。
- 接入 `ament_lint_auto`、Uncrustify、CMake lint、PEP 257 和可用的
  Cppcheck 检查。
- `normalizeAngle` 改为有界时间实现；里程计在激光时间戳处插值。
- 激光里程计输出提供非零位姿协方差和未知速度协方差。
- 720 束 360° LiDAR 不再重复首尾方向。
- 占据栅格由逐单元哈希改为 16×16 分块稠密存储，同时保留未知单元语义。
- 导航回归的场景超时使用仿真时钟，Nav2 激活另有墙钟看门狗。
- 两个自研 SLAM 回归工具的严重日志判据覆盖节点全部 10 条
  `ERROR`/`FATAL` 消息，失败时直接给出原因而不是只暴露症状。
- 候选链门限与关键帧间距的耦合已写入参数文档，并给出实测上限。

## 当前阶段保留的设计

- 点到线 ICP 仅作为离线算法对照，不接入实时前端。因此评审提出的
  KD-tree 和按关键帧分段法向估计是它接入实时链路之前的前置条件，
  不是当前运行节点的依赖。
- 相关匹配已经从同分辨率穷举改为粗到精搜索，默认局部候选数约从
  6798 降到 1620。局部参考子图目前随每个成功关键帧滑动，简单缓存会在
  正常路径中每帧失效；真正的增量缓存应和固定生命周期子图一起设计，
  暂不加入容易失效的缓存层。
- 地图保存的 launch 退出钩子仍会等待保存服务完成。这是为了保证
  `Ctrl+C` 后地图落盘的有意同步行为，最坏等待时间和原因已在代码中注明。
- 当前相关分数以每个候选落入栅格包围盒的点数归一化，因此候选之间的
  分母并非严格固定。直接改回整帧点数会重新惩罚进入新区域的扫描；走廊、
  重复结构、155 m 大场景和固定包回放均未暴露由此导致的误匹配，因此在
  2D 基线冻结时保留现状。“在预测位姿处固定有效点集合”仍可作为未来
  2D 算法研究项，但不阻塞 3D 传感器阶段。

## 验证边界

算法模块、回环处理器、地图重建队列、分块地图和容器裁剪均有纯 C++
单元测试。当前异步架构已完成 12.57 m 两圈长闭环回归：210 个关键帧、
4 次回环和 4 次完整地图重建。换用扫描法向检测后再次回归，最终误差
`0.0161 m / 0.333°`，209 次真实匹配均为 rank 2；优化地图
已成功保存为 YAML/PGM。

快速旋转已增加独立自动回归：预热后分别以 `0.30`、`0.60` 和
`1.00 rad/s` 原地旋转两圈，三档最大前端间隔均为 `0.100 s`，无拒配、
误回环或退化误报，预热和三个正式阶段共 651 次真实匹配均为 rank 2，
匹配闭合误差均低于 `0.016 m / 0.79°`。不再把
长闭环、快速旋转、走廊返回、重复结构和大场景长时间仿真列为未完成项。

单向退化走廊也已建立自动回归。可观测性处理前，25.104 m 行程的纵向
峰值为 `0.855 m`；处理后降至 `0.165 m`，横向峰值为 `0.026 m`，航向
峰值约 `0.001°`。旧回归记录了 392 条弱方向协方差消息，但该数值会复用
上一次匹配协方差，不能作为独立检测次数。新增逐次匹配诊断后，25 m
复跑的 314 次真实匹配中 rank 1 / rank 2 为 190 / 124，确认旧检测存在
39.5% 的场景内漏检。替换为法向检测后，同路线为 226 / 88；入口、出口
端墙和非对称锚点可见时 rank 2，中部长平行墙稳定为 rank 1。无拒配或
错误回环，地图横向范围保持 `2.95 m`。
随后三档快速旋转和 12.57 m 两圈长闭环均重新通过；两项回归现已把
`degenerate_events == 0` 作为硬判据，确认弱方向处理没有损伤正常观测场景。
长走廊往返自动回归也已完成：50.007 m 路线中返回位置闭合约 `0.034 m`，
最终匹配误差约 `0.101 m / 0.091°`；670 个关键帧中，物理中段 375/375
次真实匹配均为 rank 1。退化回环保护启用后仅在 rank 2 锚点区接受 3 条
真实回环并完成 3 次地图重建，最大前端间隔保持 `0.100 s`，地图横向
范围为 `3.00 m`。

重复结构回归也已完成：首次进入相隔 8 m 的相似房间时没有接受回环；
返回原房间后接受 4 条回环，逐条真值距离均不超过 `0.048 m`，无假回环
或无法分类事件。最终误差 `0.009 m / 0.044°`，4 次地图重建完整结束，
最大前端间隔保持 `0.100 s`。

大场景长时间回归也已完成：155.2 m 路线建立超过 2400 个节点，接受
42 条回环；最大前端间隔仍为 `0.100 s`，最终误差
`0.112 m / 0.016°`。最大回环 worker 为 `83.7 ms`，最大地图重建耗时
`12.12 s`；SLAM 进程平均 CPU `10.3%`、峰值 RSS `78.3 MiB`，实时率
保持 `1.000`。位姿图 Path 达到 2000 上限后保持有界。

同一路线已生成只含输入、真值和静态 TF 的固定 MCAP，并完成 2× 离线
回归：5434 帧扫描重新产生 42 条回环和 30 次完整地图重建，最终误差
`0.120 m / 0.063°`，峰值 `0.230 m / 0.619°`；543.3 s 数据用
271.7 s 墙钟完成，最大前端间隔仍为 `0.100 s`。至此本轮工程审查列出
的运行链路、退化场景、重复结构、大场景和固定数据集验证均已覆盖。

## 2026-08-03 退化检测与融合审查收尾

- 逐次 matcher 诊断现在区分接受、拒配和运动不足，并直接发布 rank、
  特征值、弱方向、实际抑制比例与法向数量；走廊检出率不再从陈旧协方差
  反推。
- 走廊测试使用真实角分辨率投射、测距噪声和不同子图深度；运行时改用
  保留原始光束索引且带表面断裂检查的扫描法向信息矩阵。弱方向修正采用
  连续缩放，避免单阈值硬切换。
- 正常长闭环和快速旋转回归要求 `degenerate_events == 0`；退化走廊按
  物理中段断言真实匹配样本数和检出比例。
- 回环默认拒绝 rank 小于 2 的候选；位姿图约束已升级为对称 3×3 信息
  矩阵，保守拒绝关闭时也可沿弱方向降权。
- 拒配和运动不足期间，激光里程计协方差按相邻里程计行程与转角传播，
  不再沿用上一次成功匹配的数值。
- Gazebo 裸轮速和 IMU 数据经适配节点补充有限、非零协方差后才进入 EKF。
  IMU 回归现会以非零退出码报告协方差、误差上限、正常路面劣化或打滑
  改善不达标。
- `/custom_slam/laser_odom` 的各向异性协方差目前用于诊断和后续融合接口，
  仓库内没有消费者；这是明确记录的前瞻接口，不是隐含的数据依赖。
- 匹配器内部已删除旧的响应曲面 Hessian 估计；节点仍会基于单帧扫描
  法向计算可观测性，供关键帧、诊断和回环使用。走廊回归的输入就绪条件
  使用所需话题集合包含关系，不会因未来增加订阅而死等。
- 数据录制 launch 与 `slam_robot_slam_3d` 的 Python 字符串统一为项目
  既有的双引号风格；同时修正 `flake8-quotes` 配置，使自动 lint 真正
  执行该约定。

## 2026-08-03 剩余观察项复核

- rank 1 的连续修正比例现在同时取信息特征值比和绝对有效法向数的较小
  缩放值；因此“绝对信息不足但比例尚可”时也一定小于 1。若强方向本身
  也低于绝对门限，仍明确判为 rank 0 并使用各向同性弱观测协方差。
- 允许退化回环的研究配置已加入集成判据。25 m 往返走廊实测接受 10 条
  回环，其中 7 条为 rank 1；弱/强平移信息比为 `0.0010–0.0339`，证明
  各向异性约束确实进入实时位姿图而非只存在于单元测试。最终误差为
  `0.046 m / 0.032°`，全部自动检查通过；默认配置仍拒绝退化回环。
- 正常两圈路线从全新 Gazebo 进程重复 3 次，每次均为 209 次 rank 2
  匹配、0 次退化误报、4 条回环。最终误差分别为
  `0.0061 m / 0.106°`、`0.0103 m / 0.751°` 和
  `0.0083 m / 0.124°`。同一代码的航向散布达到 `0.645°`，说明单次
  仿真数字的小幅变化不能直接归因于退化处理。另有单元测试逐值验证
  rank 2 时启用与禁用退化过滤得到完全相同的位姿、分数和候选计数。
- 固定 MCAP 复核处理了全部 5434 帧扫描并通过所有判据：最终/峰值误差
  `0.109/0.203 m`、`0.572/0.619°`，41 条回环、30 次地图重建、无拒配。
  固定包能排除传感器随机输入，但异步回环提交时序仍可能影响边界候选，
  因而验收继续以误差上限和事件完整性为准，不把单次末值当作逐位基线。
- 扫描法向目前仍按有效法向点等权累计，近处表面可能因角采样更密而占据
  更高权重。按表面长度加权需要重新标定门限，本轮按决定暂不引入。

## 2026-08-05 自研 3D 前端审查整改

- `LocalSubmap` 增加单调版本号，GICP 匹配器在版本未变化时复用目标点云和
  PCL 目标协方差。审查微基准的单次 `align` 从约 `94.8 ms` 降到
  `58.4 ms`；长走廊完整回调 P95 从旧基线 `92.891 ms` 降到两次复测的
  `79.187–80.628 ms`。
- 点云不再接受容差内的滞后最近邻里程计，而是等待时间戳前后样本并执行
  平移线性插值、旋转四元数球面插值。等待队列有界，过期和溢出均有明确
  诊断；长走廊 951 次匹配未触发同步告警。
- 平移、平面和偏航退化分别诊断；弱方向连续抑制后，输出协方差按实际缩放
  量放大，rank 0 使用各向同性弱观测协方差，偏航退化单独放大偏航方差。
  绝对平移信息只按对水平信息有贡献的表面法向归一化，不再被地面点占比
  稀释。
- 连续真实配准失败达到 5 次时，局部子图按轮速 + IMU 预测位姿清空并由
  当前帧重播种；无效输入和点数不足不误计为配准失败。正常走廊、旋转和
  打滑回归都要求恢复计数为零。
- 2D 自动保存的路径解析、包查找、目录创建、进程启动和超时均纳入异常
  边界；保存失败后仍必定向 `setsid` 隔离的 SLAM 进程发送 `SIGINT`。
- 所有“仿真 + 算法”复合 3D 回归入口都用 scoped `GroupAction` 隔离 include
  参数；3D 包显式声明 Eigen 依赖，GICP 的 float 旋转输出归一为严格正交
  旋转矩阵。
- `matcher.maximum_rmse` 增加启动期上界。它的平方是被接受匹配的标称方差，
  必须低于不可观测方差 `0.25`，否则 `translationCovariance` 的前置条件被
  违反并抛出——那只会表现为一条节流 ERROR，而
  `/custom_slam_3d/laser_odom` 静默停发。现在改为构造时 `RCLCPP_FATAL`
  退出，已实测 `0.6` 拒绝启动、`0.15` 正常启动。
- 地图默认输出到启动目录的行为保留。`maps/` 与 RTAB-Map 数据库的角色不同：
  数据库是没有其他入口消费的中间态工作文件，所以放在仓库外的 `~/.ros/`；
  地图是 `navigation_simulation.launch.py` 的默认输入，属于成品，留在
  `maps/` 才能让"建图 → 导航"闭环自洽。Gazebo `--force-version 8` 同样作为
  ROS 2 Jazzy + Gazebo Harmonic 的明确环境契约保留，而不是改为随宿主环境
  静默变化。
- 改为按路径而不是按策略区分产物与仓库资产：`maps/` 根目录下的
  `*.pgm/*.yaml/*.posegraph/*.data` 全部取消跟踪并加入 `.gitignore`，
  自动保存因此在物理上不可能弄脏被跟踪的文件；策展过的演示地图移入
  `maps/reference/`（gitignore 的 `*` 不跨 `/`，该子目录不受上述规则影响）。
  `reference/` 只保留 `.yaml/.pgm`，不保留合计约 `40 MB` 的
  `.posegraph/.data`——位姿图和传感器数据只对产生它的机器的"继续建图"
  有意义，clone 之后无法接着用。五个 launch 入口的默认地图路径全部不变，
  所以"自己建图 → 导航"仍是零参数；只有在尚未建图、想直接使用演示地图时
  才需要显式传 `map:=`。两份 `maps/reference/` 地图均已用
  `nav2_map_server` 实际加载验证（`239x200` / `244x204`，`origin` 与 YAML
  一致）。
- 回归的严重日志状态继续跨阶段保持粘性：任一阶段出现严重日志会使整个
  profile 失败。分阶段输出可能重复显示该失败，但不会把早期故障误当成恢复。
